# Security reporting release policy

The normative reporting process is [`SECURITY.md`](../../SECURITY.md). Fuzit has no
public release or approved public contact. Only the current private V1 candidate is
eligible for coordinated review, and reports use an owner-supplied private channel.

Release readiness requires a supported-version table, approved durable private
contact, response ownership, disclosure authority, and a tested advisory procedure.
Until the owner supplies those decisions, public issue forms and contribution
templates must redirect vulnerability reports without inventing an email address,
URL, GitHub Advisory, CVE workflow, bounty, or service-level promise.

The prepared response goals are three business days for acknowledgement and seven
business days for initial triage. Safe reproductions use synthetic repositories and
exclude credentials, private source, personal data, machine paths, hostnames, URLs,
logs, indexes, and context bundles. Disclosure remains coordinated, minimal, and
blocked until remediation, regression evidence, upgrade guidance, and owner approval
are complete.
